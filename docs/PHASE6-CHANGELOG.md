# Vela 第六阶段：中断恢复与公开仓库隐私门禁

**目标仓库唯一：** `smgsp6/3x-ui`。不重命名仓库、不更改 Go module、不直接修改原版 `docker-compose.yml`；项目本身仍是**开发预览，严禁在生产 VPS 上直接安装**。

## 本轮新增

### 1. 升级中断恢复：`vela recover`

- 更新准备阶段在停机前写入 `.pending-update`，保存原镜像摘要和目标摘要。
- 完成一致性备份后，恢复记录追加本机备份路径；这一文件**不是 Shell 脚本**，绝不使用 `source` 执行。
- 升级完成且基础健康检查通过后才更新 `image.ref` 并清理恢复记录。
- 中断的升级不会被下一次 `vela update` 覆盖；需要人工执行 `vela recover`。
- 中断发生在制作备份之前：恢复原镜像运行；中断发生在备份之后：停止候选版本、保留故障数据，再从升级前备份恢复原镜像/数据库/证书/ACME 状态。
- 恢复记录只允许本仓库的固定 GHCR SHA256 镜像、当前 Vela 目录下格式固定的备份文件。故意损坏的记录或路径会被拒绝。
- 在解包前用 Python tarfile 预检查归档，拒绝路径穿越、特殊文件和逃离数据目录的软/硬链接。若既有 ACME/证书配置包含指向目录外的符号链接，自动备份会**安全失败**并尝试恢复原服务，需要先迁移链接或人工处理。

**限制：** 这不是磁盘故障恢复的万无一失保证。突然断电后仍可能需要根据容器状态人工判断；健康接口 `204` 不能代表 Xray、Telegram 和所有节点正常。实际关机恢复需在测试 VPS 演练。

### 2. 公开仓库与 Docker 构建隐私门禁

- 新增 `deploy/vela/privacy_audit.py`，全程离线、不会上传数据，也不会把任何匹配到的密钥内容打印出来。
- 检测已加入 Git 索引的数据库、备份、私钥、机密目录；检查高置信度 Telegram Bot Token、私钥 PEM、GitHub Token、AWS Key 等签名。
- 对未纳入 Git 索引但位于普通源码目录的敏感文件、密钥文本和可疑软链接进行保守检查，降低 `Dockerfile` 中 `COPY . .` 将本地资料加入构建上下文的风险。
- 验证 `.dockerignore` 必须显式排除 `.env`、密钥、数据库与本地运行资料的必要规则；同时排除 `__pycache__`、`.pyc`，避免源码安全扫描测试的字节码意外进入构建镜像。危险的重新包含规则将阻断发布。
- 原版公开代码里的 `internal/pia/trust/serverlist_public_key.pem` 是**公开公钥**，不应与私人 TLS 私钥混淆。
- GitHub Actions PR 审查工作流加入该扫描器；补丁工具同步部署代码。

**限制：** 扫描器只识别高置信度特征与显式排除规则，不保证发现所有类型的凭证。仍必须补充 Git 全历史审计、Docker 实际构建上下文/层扫描、CI 日志审计、镜像签名和依赖供应链审计。

```text
vela backup
vela update

```
