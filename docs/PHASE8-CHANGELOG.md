# Vela 第八阶段：签名发行防重放与对话续接

## 实际改动

1. **发行清单新增 `releaseSequence`**：经离线 Ed25519 验证过的 JSON 还必须包含 1 到 9007199254740991 的整数发行序号，拒绝布尔、负数、缺失值及错误类型。
2. **防旧清单重放**：本地保存 `release.sequence`（0600，原子替换），如果文件缺失则拒绝更新；候选序号比本地序号低时立即拒绝，序号相同但 Digest 不同也拒绝。不允许借有效的老签名自动切回旧版本。旧镜像对应的旧发行序号保存在持久化更新日志中。
3. **安全回滚**：更新失败或中断恢复时，把发行序号恢复为旧镜像对应的序号；旧开发包产生的三行中断日志仅限恢复兼容，新升级写四行日志。
4. **聊天续接**：新增 `docs/PROJECT-CONTINUITY.md`，完整记录产品约定、技术边界、源码位置、真实验证情况和如何在新对话继续。

## 安全边界

- 本地序号保护是在**有固定发行公钥、运营者未丢失本机状态、攻击者没有宿主机 root 权限**下的防回放。它不是镜像漏洞防护或公钥撤销方案；首次从历史未知版本引导时仍需人工核实首个可信版本。
- CLI 依旧保留未配置的生产公钥指纹占位值：**Vela 正式更新仍故意不可用**。
- 没有创建、上传或包含任何生产密钥，也没有自动提交 GitHub。
- 回滚可能有数据库向前迁移不兼容的风险，必须在真实多节点环境测试。
