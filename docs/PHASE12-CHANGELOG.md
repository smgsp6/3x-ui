# Vela 第十二阶段：密钥文件强制保护与续签域名一致性

这是对第十一阶段开发包的增量开发，**不是生产发行版**。唯一目标为 `smgsp6/3x-ui`，保留原仓库名、Go 模块路径、原版 3x-ui 协议能力和上游更新方式。

## 本阶段新增

1. **Bot Token 读取时强制检查**：不能仅依赖 Shell 安装器的权限验证。Go 的 `tgminiapp.BotToken()` 现在拒绝组/其他用户可读的 Secret 文件、组/其他用户可写的 Secret 父目录、软链接以及 `Lstat` 与真正打开文件身份不一致的情况；限制文件大小，并拒绝内嵌换行、空白和控制字符。允许一个正常的结尾换行。只读本地 Secret，不从环境变量回退。
2. **TLS 自动续签身份保护**：证书与私钥正确、有效期增长，仍不足以安全切换。热加载器新增证书域名与 IP SAN 继承检查，拒绝将面板当前证书自动换成另一个域名的证书。如果管理员要改面板域名，必须经过明确的配置审查、重启和验证；普通 ACME 同域名续签不受影响。
3. **上游兼容核查**：使用 GitHub 连接读取 `smgsp6/3x-ui` 当前 `main` 的 22 个待修改文件，所抽取的 22 个关键修改锚点均唯一匹配。此项验证比纯合成源文件模拟更接近实际，但**不等于每个完整替换块都已经实仓应用或整仓编译成功**。
4. **补丁交付完整性**：第三方模块独立 Go 测试和新合同测试随补丁一起复制到目标开发分支，并保持之前的拒绝修改 `main`、拒绝未审计 HEAD、隐私扫描等限制。

## 仍然阻止正式发布

- 当前无法完整编译 Go 1.27.4 / Node.js 26 的原版项目，也没有本地真实 Docker 或 Telegram Bot 端内验证。
- `vela update` 的正式发布签名公钥与正式镜像 Digest 未配置：**拒绝生产更新是预期行为**。
- 真正的 Git 全历史、Docker builder 缓存和发布镜像层审计需要在可信 CI 环境里执行；本包没有使用或导出用户的真实 Token、私钥、数据库或服务器信息。
- 独立证书申请、主动续签、完整 UI、多节点端到端测试、一键安装仍未完成。
