# Vela 第七阶段：签名发布门禁、密钥保护和幂等恢复

唯一目标仓库：`smgsp6/3x-ui`；Go module 不改，原版 `docker-compose.yml` 不改。仍是开发预览，**不能生产安装**。

## 本轮实装

1. **Git 历史敏感文件扫描**：新增 `deploy/vela/git_history_audit.py`，用 Git 批处理读取可达历史 Blob，不输出密钥原文；即使凭据后来被删除仍可触发阻断。CI 的审查任务采用完整历史检出，新增 3 项模拟历史测试。若原版历史存在可疑对象，正式发行前需要人工核实，不能绕过阻断。
2. **发行清单 Ed25519 验证**：`vela update` 在解析发布 JSON 之前，先检查本地公钥文件 SHA256 指纹及 `stable.json.sig` 签名；指纹尚未正式设置时直接拒绝更新，绝不使用 `latest`。
2. **Bot Token 不从环境变量取值**：只读取 `XUI_TG_MINIAPP_BOT_TOKEN_FILE`，并通过 `Lstat` 拒绝符号链接、非普通文件和异常大文件；受限读取防止并发文件大小改变。
3. **证书状态最小披露**：管理 API 不再序列化证书/密钥的服务器路径，移动端 UI 改为显示密钥匹配状态，附新增的 JSON 安全测试。
4. **支持自定义面板端口**：Compose 明确传入 `XUI_PORT`，维护 CLI 在不执行 `.env` 的前提下解析端口。管理口只在环回监听，仍需要可信 HTTPS 代理。
5. **恢复再次中断后的重试**：`vela recover` 在具有有效恢复记录时允许部分目录缺失，模拟恢复过程断电之后能用原备份重建数据。
6. **补丁对抗符号链接**：拒绝覆盖新路径中的已有符号链接，部分文件复制失败会清除不完整写入，并恢复原源码。
7. **发行者操作手册**：新增 `docs/RELEASE-SIGNING.md`，说明离线私钥、签名公钥的分发与指纹固定流程。

## 安全限制

- **没有生产签名密钥**；代码中仅保留不可用的签名指纹占位值，所以本阶段的 `vela update` 不具备生产更新能力。
- 离线的“正常升级/失败恢复”测试使用临时 Ed25519 测试密钥签名模拟清单；真实 GitHub Actions、Docker、Telegram 和 VPS 尚未通过端到端验证。
- 不支持在发生不可逆数据库迁移或外部 PostgreSQL 数据变更后保证自动恢复；需要独立迁移/备份策略。
- 恢复过程的反复断电依旧可能需要人工检查，新的模拟测试不代替断电实机测试。
- 证书页当前仍为**只读状态**，证书写入、续签和提醒尚未完成。

## 测试位置

- `tests/test_maintenance_cli.py`：签名缺失、签名篡改、公钥替换、自定义端口、中途断电恢复、普通升级和回滚。
- `tests/test_apply_to_repo.py`：严格 Fork 限定、版本锁定、符号链接拒绝、文件部分复制失败后的恢复。
- `internal/web/service/tgminiapp/*_test.go`：Bot Token 文件校验及证书状态不暴露文件系统路径。
