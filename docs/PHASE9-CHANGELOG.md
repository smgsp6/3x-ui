# Vela 第九阶段：证书到期提醒（开发预览）

本阶段保持 `smgsp6/3x-ui` 仓库与 `github.com/mhsanaei/3x-ui/v3` 模块路径原样，默认不对外发送证书资料。

## 新增功能

- `internal/web/service/tgminiapp/certificate_alerts.go`：证书到期通知、提醒阶段去重、仅本地私有状态文件。只检查原有管理面板及订阅证书的**有效期和配置状态**，绝不自动上传证书或密钥。
- 与原版 cron 整合，只有 `XUI_TG_MINIAPP_ENABLED=true` 且 `XUI_TG_CERT_ALERT_ENABLED=true` 时，才在服务器的面板时区每天 **09:00** 尝试通知。默认关闭。
- 接收对象来自 `XUI_TG_MINIAPP_ADMIN_IDS`，只允许正整数私聊用户 ID；群组、频道、话题均拒绝。
- 文本只包含“管理面板 / 订阅服务”、证书状态及约剩余天数。**不包含域名、IP 地址、签发机构、真实管理员 ID、文件路径、Token 或私钥**。Telegram 仍会看见你发送的通知文字及收件账号，需管理员明确决定启用。
- 状态持久化至 `/etc/x-ui/vela-cert-alerts.json`，权限为 `0600`，只含 SHA256 去重键与发送时间；已通知某证书的同一预警阶段不会因容器重启重复发送。
- 证书到期阶段：30 / 14 / 7 / 3 / 1 天、已过期、配置异常；仅在进入新阶段后通知（可能跳过不曾经历的阶段）。发送失败下一次检查再试。失效状态文件或符号链接路径时拒绝发送。
- 修复 Telegram Mini App 启动按钮在群聊中可能误显示的问题：现在只显示在**白名单管理员的私聊**。
- 独立证书管理页面显示“到期提醒是否启用”，依旧只读。**自动签发和自动续签尚未独立实现/验收**。

## 使用前须知

- 这一代码包仍然只是开发预览；GitHub 没有提交，真实 Telegram／Docker／整仓构建尚未验证。
- 开启提醒需要已正确配置官方 Telegram Mini App、Secret 文件及 HTTPS 反向代理。通知依赖正在运行的 Vela Bot；不要在群组中开启。
- `/etc/x-ui` 必须持久化到本地私有卷，状态目录不可被其他用户写入，不能是符号链接。损坏的提醒状态**不会覆盖**，请先人工核查而非强行清空。
- 原版 ACME 续签和证书管理功能与本模块分别独立；提醒不等于完成自动续签。
- 多节点每台服务器若分别启用提醒，可能产生多条同类通知；集中化告警去重仍属后续范围。

## 测试与限制

- `GO111MODULE=off go test -race -count=1 ./internal/web/service/tgminiapp`：测试本模块，包含授权 ID、隐私文本、重启去重、错误重试、状态文件保护、预警里程碑等。
- `python3 -m unittest discover -s tests -p 'test_apply_to_repo.py' -v`：在**合成 Fork** 上验证补丁安全策略，不能代替原版真实整仓构建。
- 本地运行环境无 Docker、Go 版本低于上游 1.27、Node 低于 26；不能宣称生产可安装。
