# Vela 第十阶段变更记录（开发预览）

## 本次修复

1. **证书提醒 UI 状态不一致**：原接口把 `alertsEnabled` 放在 JSON 顶层；原版前端 `HttpUtil._respToMsg` 只保留 `success/msg/obj`，造成提醒即使启用也被页面显示为关闭。现将 `alertsEnabled` 与 `certificates` 一起放在 `obj`，并让 React 页面严格检查数据结构，避免静默误报。
2. **管理面板 TLS 证书续签后热加载**：新增 `tgminiapp.TLSCertificateReloader`，仅在 `XUI_TG_MINIAPP_ENABLED=true` 且面板**直接使用 Go HTTPS** 时启用。每隔至少 30 秒，在下一次 TLS 握手时检查磁盘证书与私钥是否构成有效配对；只有完整、可解析、匹配且不超过文件大小上限时才切换后续握手。半写入、错配、损坏的证书继续使用之前的有效配对；不会执行 shell、写证书、上传证书或泄露私钥。
3. **防止错误证书抢占可用 HTTPS 连接**：热加载前检查证书是否已生效、尚未过期，并拒绝到期日比当前证书更早的替换。它不是完整 CA 信任链验证，浏览器仍负责主机名和信任链验证。
4. **补丁工具目录安全**：拒绝现有临时符号链接、符号链接父目录；修改时用 `O_CREAT|O_EXCL|O_NOFOLLOW` 创建临时文件、写盘同步后原子替换；新增恶意符号链接测试，避免局部开发环境的路径攻击。
5. **API 与前端契约回归**：新增离线跨文件断言与证书热加载 Go 单元测试，覆盖新证书切换、半写入失败回退、超大 PEM 拒绝及并发读取。
6. **后续上游升级保护**：只在 Vela 模式额外设置 `tls.Config.GetCertificate`，默认非 Vela 模式完全维持上游行为；仓库 `smgsp6/3x-ui` 和 Go 模块路径不变。

## 重要边界

- **这不负责签发或主动续签**：沿用上游 `x-ui`/ACME 或外部 Certbot 续签；新模块仅解决 Go 管理面板将成功续签的文件用于**新 HTTPS 连接**的问题。不能保证配置不当、过期、链不完整的证书被外部客户端信任。
- 使用 Nginx / Caddy / Traefik 终止 HTTPS 时，由该反向代理负责自己的证书热加载；本模块不会修改反向代理。
- 正式生产前必须检验真实 Docker、Telegram WebView、前端 typecheck、完整 Go 编译、TLS 握手、升级回滚、多节点兼容和镜像隐私审计。
- 本阶段压缩包**不是正式安装包**，不会自动修改 GitHub 仓库或生产服务器。
